# MIO 眼神表演约定

## 目的

眼形承担主要表情；高光补充注意力与情绪。待命的角色应当安静但有回应。运动需要有起因、停顿和收束，避免把持续随机运动当成生命感。

## 参考与适用边界

[Disney Research — Realistic and Interactive Robot Gaze (IROS 2020)](https://la.disneyresearch.com/publication/realistic-and-interactive-robot-gaze/) 将注意引擎、行为选择和动作库分层，用注意目标驱动行为，并采用动作错拍、拖随和缓入缓出来组织机器人眼神。

本项目借用这些表演组织原则。下述面光形状、具体尺寸、幅度和节奏属于 MIO 的美术与实现选择，并非该研究对高光形状的结论，也没有把抽象双眼当作真实人眼的光学模拟。

## 高光

- 一块柔边、低对比的紫色面光依附在眼面上。颜色采用浅紫而非近白色，避免小而亮的标记抢走眼形的表达。
- 默认面光宽为眼宽约 46%，高为眼高约 50%，面积约占眼面 23%，不含模糊边缘。透明度约 32%；不同表情的亮度上限不超过 43%。保留柔边并使用较浅的紫色，折中清晰度与视觉分量。
- 面光继承整双眼睛与单眼的旋转、弹性压缩及眨眼。眼睛弯曲时，面光使用同一曲面上的位置、切线与曲率，不维持屏幕方向，也不自行旋转。
- 主面光在待命时位置、尺寸固定；亮度只有约 ±1.8% 的慢呼吸。它不在眼睛里巡游。
- 两块次级矩形反光使用约 14 秒的同向穿行节奏，交错淡入淡出；宽为眼宽约 14% / 20%，高为眼高约 11% / 15%，亮度约 0–9%。两眼节奏一致，不旋转、不闪烁；返回起点时必须已完全隐去。情绪与注意力仍由主面光主导，困倦/专注时压低次级光。关闭自然动作或启用减少动态效果时暂停流动。
- 注意转移时，内部标记随实际视线小幅平移，略迟于眼形并平稳收住，避免每个鼠标抖动都制造一次表演。
- 追踪由整体视线位移、眼内面光偏移与眼形共同完成。水平视线范围约 ±40 个模型单位，垂直约 ±28；位置响应采用临界阻尼，不在目标周围晃动。面光根据自身宽高限制偏移，避免移出眼面。
- 朝目标一侧的眼睛微微舒展，另一侧轻收；水平追踪时眼距略缩小。向下看时微眯，向上看时微睁，并配合很小的倾斜。单眼宽高变化控制在原表情的约 11% 以内，保留原表情的曲率和主要比例。
- 明确的注意变化或情绪切换只触发一次轻微提亮：约 120ms 达峰，约 680ms 收束，随后保持。不会循环闪烁。
- 情绪改变面光的位置、宽高、亮度和两眼间的相对强弱，沿连续参数过渡；眨眼时与眼形一同压缩、变暗。

## 轮廓与构图

矩形与开心弯带均不使用显式圆角；边缘以约眼睛短边 4.5% 的模型尺度进行透明度渐变，柔和连接背景，而不是在外侧附加一个清晰的描边。

沉浸模式共用 getLayout：纵向拉长 1.28 倍，静止中心位于屏幕高度约 43%，纵向注视整体位移乘以 0.7。16:10 屏幕上的待命眼高约为屏幕的 45%，文字随新的眼形布局下移。超宽、竖屏及所有极端注视方向仍须完整留在屏幕内。

## 各状态的动作台本

| 状态 | 眼形与视线 | 高光 |
| --- | --- | --- |
| 待命 | 主要朝前，长时间保持；约 6s 时有一次很小的侧上方检查，然后回到正前 | 宽而淡的稳定面光，只有微弱亮度呼吸 |
| 开心 | 弯曲长方形眼带轻轻上提，低幅度呼吸 | 面光舒展到眼宽约 64%，随眼带弯起，略微提亮 |
| 好奇 | 不对称睁眼，小幅倾斜；优先追随用户指向 | 睁得更大的眼睛，面光也更舒展、更明亮 |
| 思考 | 向侧上方凝视；停约 2s 后小幅调整，保持约 1s，再回到原思考方向 | 面光向侧上方收拢，随思路调整轻移 |
| 专注 | 朝目标稳定凝视，取消水平周期扫描，自动眨眼间隔更长 | 低矮、横向延展的亮面，亮度呼吸进一步减小 |
| 惊讶 | 短暂睁大，随后保持 | 面光面积扩大，温和提亮，随眼形保持 |
| 困倦 | 缓慢垂落与微眯 | 面光降低、压薄、变淡 |
| 困惑 | 不对称眼形与轻微倾斜，等待输入 | 面光配合两眼的高低、倾斜与强弱，等待明确目标后才移动 |

浏览器调试台中，光标跟随覆盖整个页面，包括控制区。手动视线保持到下一次光标移动，光标优先于自动台本与思考方向。用户正在交互时，自动侧看不会抢走注意力；光标静止时保持注视，离开页面后停约 650ms，再平滑回归。

安装后的 KDE 桌面版通过 KWin D-Bus 桥读取整个系统的光标，并将全局坐标映射到每块显示器。静止时持续保持最后一个有效目标，不能把没有移动事件理解成坐标失效。Wayland 上不使用无窗口焦点的 QCursor 原点读数；未知坐标时保留当前情绪的自然视线。多屏时，每块屏幕各自朝同一目标方向响应；普通浏览器调试和 Plasma 原生壁纸插件共用 `eyes-core.js` 中的眼形、高光与弹簧参数。浏览器使用 Canvas，桌面使用 GPU 连续曲面绘制，旋转、弯曲、眨眼和注意力均由同一模型驱动。桌面按刷新帧推进弹簧，不用整屏 Canvas 与固定间隔计时器。

## 回归验证

`node tests/eyes.test.mjs` 检查面光继承眼睛旋转、曲率一致、表情轮廓有区别、主面光静止时不自行游移和变形、次级光的低亮度/边界/循环连续性、两眼注意一致、长期运行稳定、面积与对比约束、注意事件的收束，以及思考与专注的停顿节奏。

视觉检查应包含：待命至少观察 10s；连续改变鼠标方向后停止；依次进入思考、专注与开心；验证全屏和竖屏，并确认小高光不会被眼形边缘裁掉。
